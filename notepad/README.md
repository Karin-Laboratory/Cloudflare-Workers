# Karin Notepad リアルタイム同期版

公開 URL: https://notepad.karin-lab.com

Windows のメモ帳をイメージした、Cloudflare Workers 上のテキストエディター。

## 構成

- GitHub: モノレポの `main` ブランチにある `notepad/worker.js`。旧 `notepad-web` ブランチは履歴保存用に残します。
- Cloudflare Workers: `karin-notepad`
- Cloudflare Access: 本人メールアドレスのみ許可するメールOTP。セッション有効期限 720h (30日)
- Durable Objects: `NotepadRoom` (WebSocket、変更内容の即時配信と調停)
- D1: `karin-notepad` (文書と保存履歴)

## 保存と同期

入力後約180ミリ秒のデバウンスで WebSocket に送信し、D1への書込後、接続中の各端末に新版を配信する。通常のネットワーク条件なら数百ミリ秒程度を目指す（通信状態やD1応答による遅延あり、実測保証なし）。

本文全体をリビジョン番号・ベース本文付きで送信し、サーバーが最新本文との変更区間を照合する。別々の箇所への編集は統合し、同じ箇所に競合が発生すると選択ダイアログで採用版を決める。競合コピーは自動生成しない。**OT/CRDTによる完全な共同編集エンジンではなく、重なる操作・複雑な編集に制約がある。**

切断時はブラウザの localStorage に下書きを退避。再接続後に復帰する。別端末の現在の内容と統合できない場合、画面で選択を求める。

Undo/Redo は端末内の直近の編集操作を対象とし、クラウドでは D1 に直近60リビジョンの履歴を残す。右上の「履歴」から以前の版に戻せる。

Ctrl+S はクラウド保存、Ctrl+Shift+S はローカルPCへダウンロード保存。

## 制限・注意

- 1文書最大50万文字、最大100文書
- ブラウザ更新によって編集中のUndoスタックは消える。保存履歴はクラウドに残る。
- 同期処理中やオフラインでは必ず右上の保存状態を確認する。
- 別端末のリアルタイム同期はWebSocket接続中に機能する。ブラウザでのA/B同時編集の実機検証は別途必要。
- Cloudflare Workers Buildsによる自動デプロイが有効です。`main` の `notepad/**` を監視します。更新時はGitHub ActionsとCloudflare Buildsの結果を確認してください。
- Microsoft公式アプリではない。

## GitHub自動デプロイ設定

正式ソース: `Karin-Laboratory/Cloudflare-Workers` の `main/notepad/`。Worker script: `karin-notepad`、main module: `worker.js`、compatibility_date: `2026-09-01`。

Bindings: `DB` = D1 `karin-notepad`; `ROOM` = SQLite backed Durable Object `NotepadRoom`、migration tag `v1`。

Cloudflare Workers Builds: branch `main`、root directory `/notepad`、watch paths `notepad/**`、build = `npm install --no-audit --no-fund && npm run check && npx wrangler deploy --dry-run`、deploy = `npx wrangler deploy --keep-vars`。

D1、Durable Objects、カスタムドメインの設定は `wrangler.jsonc` に定義します。Accessの設定はCloudflare側で管理し、公開リポジトリに認証情報を保存しません。

## ファイル名の自動提案（2026-10-11）

- 新しい文書は、本文の**1行目の先頭9文字**から自動で仮ファイル名を作成し、`.txt` を付けます。例：`スマホやPC作業で、ちょっとめもしたいとき。` → `スマホやPC作業で.txt`。
- 未確定の間は入力・編集・Undoに応じて仮名が変わり、その仮名もD1で同期します。本文は従来通り自動保存します。
- 初めて手動の「クラウドへ保存」（Ctrl+S、スマホ下部の保存ボタン）を実行すると、仮名を初期値にした名前確認ダイアログが出ます。内容を変更してもOKです。確定すると以降の本文編集でファイル名は変わりません。
- 確定後の変更は、PCの「ファイル > 名前を変更」またはスマホの「その他 > 名前を変更」から行えます。
- PC/スマホへファイルを書き出す際も、現在の名前を初期値にして変更できます。
- 既存の `無題.txt` は本文を変更せず、仮名モードに移行しました。


## 1行目による自動分類（2026-10-30）

1行目が `削除` の文書は「ごみ箱」、`完了` または `終了` の文書は「アーカイブ」に自動分類します。前後の空白は無視しますが、`削除予定` などの部分一致は対象外です。分類は本文から毎回算出するため、別の状態文字列や通常の文章に変更すると自動的に移動します。

分類中のファイル名は `削除(2行目の先頭10文字).txt` / `完了(...).txt` / `終了(...).txt` とし、2行目の変更にも連動します。2行目が空欄の場合は次の空白でない行まで読み飛ばし、すべて空欄なら `内容なし` とします。ファイル名に使えない文字は空白に置換します（Unicodeの文字単位で最大10文字）。分類中は手動改名不可です。

「クラウドから開く」の直下に通常ファイルを表示し、その後ろに展開可能な「📁 アーカイブ」「📁 ごみ箱」を配置します。通常ファイルだけを独立したスクロール枠にし、フォルダ見出しはその下に常時見えるよう配置します。フォルダはダイアログを開くたび初期状態で折り畳みます。PC・スマホ共通で、検索は全フォルダを横断します。フォルダ内の文書もそのまま開いて編集できます。

通常の名前が手動確定済みの場合は、状態指定を外した時点で元の名前に戻します。未確定の場合は従来どおり1行目から名前を生成します。文書ID・保存履歴・既存のリアルタイム同期は維持します。ごみ箱への移動はクラウドの完全削除ではありません。既存の100文書制限にはアーカイブ・ごみ箱を含みます。

## クラウドから開く・閉じる（2026-10-11）

- 「ファイル → クラウドから開く」からD1に保存されている文書を名前・更新日時付きで選びます。スマホでは「その他 → クラウドから開く」。名称で絞り込みできます。
- タブの「×」は**クラウドから削除しません**。閉じたタブは同じ端末では閉じた状態を維持し、上記メニューから再度開けます。
- 保存後に変更がないときは確認なしでタブだけを閉じます。
- 未送信・送信中の編集があるときは「『ファイル名』の保存後の変更が失われます。閉じますか？」と表示し、**上書き保存する／変更を破棄して閉じる／キャンセル**の3択にします。
- 「上書き保存する」はD1での保存完了を待ってタブを閉じます。「変更を破棄して閉じる」は未送信の編集を破棄し、送信済みで未確定の編集がある場合は必要に応じて保存直前の版へ復元してから閉じます。「キャンセル」は編集に戻ります。
- 現時点ではクラウドから完全削除するUIは用意していません。意図しない削除を防ぐためです。
- クラウドの保存一覧は本人のCloudflare Access認証下でのみ閲覧できます。別端末では「クラウドから開く」から再開してください。
- この変更はフロントエンドのみで、Durable ObjectsとD1の保存データは削除・変更していません。
